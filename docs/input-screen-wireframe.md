# StyleScope Input画面 WF

StyleScopeのInput画面は、Figma参照のように「大きな投入エリア」と「文章入力バー」を中心にした、軽い入口画面として扱います。
主対象はAIバイブコーダーなので、最初の画面では設定を見せすぎず、画像でも言葉でもすぐ分析へ進める状態を優先します。

---

## 1. 画面の目的

```yaml
screen: Input
purpose: "参考画像または雰囲気の言葉を入れて、AI分析に進む"
primary_user: "AIバイブコーダー / 個人開発者"
main_action: "ファイル選択または文章入力からResultへ進む"
visual_reference: "Figma Style node 2:41"
input_model_v1: "画面上はモードタブを出さず、画像枚数またはテキスト入力からResult表示を出し分ける"
```

この画面で大事にすること:
- 入口は軽く、説明や設定を出しすぎない。
- 画像入力とテキスト入力を同じ画面で自然に受け入れる。
- Figma参照のように、広い余白・薄いグレー面・黒いアクションで静かな印象にする。
- Result画面では入力内容に応じて `複数画像の共通点` / `このスタイルの構成要素` を出し分ける。

---

## 2. 表示優先度

```yaml
priority_order:
  1: "Brand / StyleScope"
  2: "Hero Copy / What Style do you want?"
  3: "Large Drop Area / 画像投入"
  4: "Text Input Bar / スタイルイメージの文章入力"
  5: "Footer"
```

補足:
- `画像1枚 / 複数画像 / テキスト` は画面上のタブでは出さない。
- 画像枚数が1枚なら `single_image`、2枚以上なら `image_set`、文章のみなら `mood_text` としてResult側で扱う。
- 入力例は独立セクションではなく、入力バー内の薄いplaceholderとして出す。
- 補足テキストやAnalysis Setupはv1デモのInput画面では前面に出さない。

## 5. Resultへの受け渡し

```yaml
payload_inference:
  single_image:
    condition: "画像が1枚"
    result_component_heading: "このスタイルの構成要素"
    result_source_mode: "Image"
  image_set:
    condition: "画像が2枚以上"
    result_component_heading: "複数画像の共通点"
    result_source_mode: "共通点分析"
  mood_text:
    condition: "文章のみ"
    result_component_heading: "このスタイルの構成要素"
    result_source_mode: "Mood Text"
```

Result側で使うルール:
- 画像が2枚以上のとき、構成要素セクション内に `複数画像の共通点` を表示する。
- 画像1枚またはテキスト入力のとき、構成要素セクション内に `このスタイルの構成要素` を表示する。
- Source Summaryでは、画面上に `Image Set` のような内部ラベルを強く出さない。
